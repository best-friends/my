# ADR-0021: リポジトリ内の文書は現在の状態だけを記述し、履歴は git に任せる

- Status: Accepted
- Date: 2026-10-16
- Deciders: @rosylilly
- Issue: —

## Context

変更の履歴は git（コミット・PR・Issue）が持つ。リポジトリ内の文書に「初版からの変更」「当初は〜だった」「旧案」などの経緯を書くと、次の問題が起きる。

- 履歴が git と文書の二重管理になり、どちらが正しいか分からなくなる。
- 読み手（人間とエージェント）が、現在の決定と過去の経緯を読み分ける必要がある。
- 文書が変更のたびに長くなり、「今どうなっているか」が埋もれる。

## Decision

- **ソースコード・設計文書・要件・手順書など、リポジトリ内のすべてのファイルは「今」を記述する。** 変更の経緯・旧版との比較・変更履歴の節は書かない。経緯はコミットメッセージと PR の説明に書く。
- **ADR は「この決定をした」という現在の事実を記録する。1 つの判断につき 1 ファイル** とし、判断が増えればファイルが増える。
  - Accepted の ADR を覆すときは、本文を書き換えず、新しい ADR を書く。旧 ADR の Status を `Superseded by ADR-XXXX` にする（ADR-0000）。
  - Proposed の ADR は、まだ決定ではないので、その場で書き換えてよい。そのときも「前の案では〜」とは書かず、現在の案だけを書く。
  - Context には、決定が必要になった **問題** を書く。それまでの案の変遷は書かない。
  - 却下した選択肢は「Considered Options」に、現在の比較として書く（「以前はこれを推奨していた」とは書かない）。
- **Open Questions には未解決の事項だけを書く。** 解決したら、その結論を本文（Decision / Consequences）に現在形で書き込み、項目を消す。完了のチェック（`[x]`）は残さない。
- 外部の事実（価格・制限値）の **確認日と出典** は、記載している値の属性なので書いてよい。

## Consequences

- 文書を読めば現在の状態が分かり、経緯は `git log` / `git blame` / PR で辿れる。
- 経緯を知りたい読み手のために、コミットメッセージと PR の説明に「なぜ変えたか」を必ず書く。
- エージェントは、文書を更新するときに変更履歴の節を足さない（AGENTS.md と ADR の手順書に明記する）。
