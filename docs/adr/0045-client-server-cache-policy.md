# ADR-0045: キャッシュの方針（クライアントとサーバー）

- Status: Proposed
- Date: 2026-10-19
- Deciders: @rosylilly
- Issue: #485

## Context（背景・課題）

決定者のフィードバック（#485）: 「プロフィールページを開く → 新規に投稿 → 再度プロフィールページを開いた時などに古いキャッシュのまま（最新の投稿が出ない）」。

本物の `my serve`（SQLite）と Playwright で再現した（spike: [`spike-485.spec.ts`](https://github.com/best-friends/my/blob/99c9bb27a476da3e9f641a08d88c634ca2e6b7c9/app/web/e2e/spike-485.spec.ts)、API の GET に 800 ms の遅延を足して本番の往復を再現）。
プロフィールを開いたあとに投稿し、もう一度プロフィールを開くと、まず投稿前の一覧が出て、往復の時間のあとで新しい投稿に入れ替わる。
再読み込みのあと・ブラウザの「戻る」でも同じになる。
原因はクライアントだけにある。

- 投稿は一覧に無効化の印を付ける（`invalidateQueries`、既定の `refetchType: "active"`）だけで、表示していないプロフィールの一覧は取り直さない。
  web-client.md S7 の loader は `staleTime: "static"` で読むので、印を見ずにキャッシュを返す。
  S1 はこの場合に `refetchType: "all"` で取り直して待つよう決めているが、従っているのは管理画面（`refreshQueries`）だけで、投稿・フォロー・ブロック・ミュートは従っていない（#504）。
- TanStack Router の `defaultStaleReloadMode` は既定で `"background"` で、前に訪れたルートの match が残っていると loader の終わりを待たずに前の match のまま描画する。
  部品は Query のキャッシュ（古い一覧）を読み、マウント時の取り直しが終わってから入れ替わる。
  loader が無効化の印を見て取り直しても、それを待たずに古い一覧が先に出る。
- プロフィールの保存は `verify_credentials` だけを書き換え、プロフィールの見出しと投稿の作者名は古いまま残る（#505）。

サーバーの応答と Service Worker は原因ではない。
閲覧者つきの client API の応答は `Cache-Control: no-store`、匿名の応答は `public, max-age=60` に `Vary: Authorization, Accept-Language` が付き、Service Worker は `/api` に答えない（ADR-0028）。
spike では、閲覧者つきの GET はすべて `no-store` で、Service Worker を通った応答はなかった。

S1 のいまの決まりは、書き込みごとに「どの画面のどのクエリが loader で読まれるか」を書き手が知っていて、表示していないものまで取り直すことを求める。
守るのは書き込みの数だけの注意で、守れていないことが今回の不具合になった。
データの種類ごとに、誰がいつ無効化し、いつ取り直すかを一つの方針にまとめる。
サーバーの `Cache-Control` も、いまの値を方針として書き留める。

関連: ADR-0016（client API の作法: 匿名の公開 GET をキャッシュ可能にする）、ADR-0025（TanStack Router・Query）、ADR-0028（外枠の HTML と PWA、Service Worker）、web-client.md S1・S7・S10・Y7、#203（Service Worker のキャッシュを複雑にしない）。

## Decision Drivers（判断基準）

- 自分の書き込みのあとに開いた画面は、最初の描画から書き込みを反映している（古い表示を一瞬でも出さない）
- 書き込みを書く人が覚えることが少なく、忘れても古い表示が残り続けない
- 戻る・タブの切り替えなど、書き込みのない移動はキャッシュから即座に描画する（web-client.md E4）
- 読んでいるタイムラインの先頭を勝手に変えない（Y7）
- サーバーのキャッシュは、閲覧者ごとに違う応答を他人や匿名の訪問者に返さない
- ゼロに近い運用コストのまま、匿名の公開ページは CDN で受けられる（ADR-0016）

## Considered Options（選択肢）

クライアント:

1. いまの S1 を全部の書き込みで守る: 書き込みごとに、表示していないクエリも `refetchType: "all"` で取り直して待つ
2. loader が無効化の印を見て、ルートの再読み込みを待つ: loader は `staleTime: Infinity` で読み、ルーターは `defaultStaleReloadMode: "blocking"` にする。書き込みは印を付けるだけ
3. キャッシュをやめる: `staleTime: 0` にして、画面を開くたびに取り直して待つ
4. サーバーから無効化を知らせる: 自分の書き込みの結果をストリーミング（SSE）で受けて無効化する

サーバー（client API）:

1. いまのまま: 閲覧者つきは `no-store`、匿名の公開 GET は `public, max-age=60` と `Vary: Authorization, Accept-Language`
2. 閲覧者つきの応答にも ETag を付けて条件付き GET で再検証する

## Decision（決定）

> Proposed の間は推奨案。

クライアントは選択肢 2、サーバーは選択肢 1 を推奨する。

### クライアント（TanStack Query と TanStack Router）

- **TanStack Query がサーバーのデータの唯一のキャッシュ**（S1）。ルーターは自分のデータを持たない（`defaultPreloadStaleTime: 0` のまま）。
- **loader は「キャッシュにあって無効化されていなければそのまま、なければ・無効化されていれば取って待つ」で読む**: `queryClient.query({ ...options, staleTime: Infinity })`（無限スクロールは `infiniteQuery`）。
  `staleTime: "static"` は無効化の印を見ないので loader では使わない。
- **ルーターは再読み込みを待つ**: `routerOptions` に `defaultStaleReloadMode: "blocking"` を置く。
  無効化されていないクエリは loader が即座に返すので、書き込みのない移動はいままでどおりキャッシュから即座に描画する。
  無効化されたクエリがある画面だけ、取り直しが終わるまでいまの画面を残す（遷移は `startTransition` の中、E4）。
- **書き込みは、確かに分かる変化をキャッシュに書き、一覧は印を付ける**:
  - 応答で分かる単体のデータ（投稿・閲覧者・関係・設定）は `setQueryData` / `updateCachedStatuses` で書く（いまどおり）
  - 並びや件数が変わり得る一覧は `invalidateQueries`（既定の `refetchType: "active"`）で印を付ける。表示中のものはその場で取り直し、表示していないものは次に開いたときに loader が取り直して待つ
  - 書き込みの成功表示は、表示中のクエリの取り直しを待ってから出す（`await invalidateQueries(...)`）。表示していないクエリの取り直しは待たない。`refreshQueries`（`refetchType: "all"`）は要らなくなる
- **書き込みが変えるクエリは、その書き込みの関数の隣に書く**: `features/<x>/api` に書き込みごとのキャッシュ更新関数（`cachePostedStatus` のような）を置き、部品の `onSuccess` はそれを呼ぶだけにする。
  テストは「書き込み → 別の画面を開く → 最初の描画から反映している」を、遅延のある MSW で確かめる。

データの種類ごとの方針:

| データ | 書き込みのあと | 時間で古くなったとき（既定 `staleTime` 30 秒） |
| --- | --- | --- |
| 閲覧者（`verify_credentials`）・設定（`preferences`） | 応答で書き換える。プロフィールの保存は、閲覧者のアカウント（`lookup`・`/accounts/{id}`）を書き換え、閲覧者の投稿を含む一覧の埋め込みアカウントを差し替えるか印を付ける | 画面を開いたときに裏で取り直す |
| アカウントと関係（`lookup`・`/accounts/{id}`・`relationships`） | 関係を応答で書き換え、件数を持つアカウント、フォロー一覧、ホーム、ブロック・ミュートの一覧に印を付ける | 同上 |
| 投稿単体（`/statuses/{id}`）と、各一覧の中の同じ投稿 | お気に入り・ブーストなどはすべてのキャッシュの写しを書き換える（楽観的更新、S8）。削除は写しを除く | 同上 |
| 一覧（タイムライン・プロフィール・タグ・スレッド） | 新しい投稿で、入り得る一覧に印を付ける | 画面を開いたときに裏で取り直す。読んでいる間は取り直さない（フォーカス・再接続では取り直さない、Y7）。ホームの新着はストリーミングが「N 件の新しい投稿」に溜める（S10） |
| 通知と未読数 | 既読は応答で書き換える | ストリーミングが未読数を書き換え、一覧に印を付ける（S10） |
| インスタンス情報 | 管理画面の書き込みが印を付ける | 画面を開いたときに裏で取り直す |
| 管理画面の一覧と件数 | 書き込みが、その書き込みで変わる一覧・件数・監査ログに印を付ける | 同上 |

すべてのデータに共通:

- 利用者が変わったら全部を捨てる（`removeQueries`、いまどおり）。表示言語が変わったら全部に印を付ける（いまどおり）。
- 別のタブ・別の端末での書き込みは知らせない（v0）。次に画面を開いたときに、`staleTime` を過ぎていれば裏で取り直す。

### サーバー

| 応答 | `Cache-Control` | ほか |
| --- | --- | --- |
| client API の閲覧者つきの応答（`Authorization` あり）とエラー | `no-store` | 公開のインスタンス情報など、閲覧者の言語だけで変わるものは `private, max-age=60` |
| client API の匿名で取れる公開 GET の匿名の応答 | `public, max-age=60` | `Vary: Authorization, Accept-Language`。匿名の訪問者には最大 60 秒古い一覧が出る |
| ストリーミング | `no-store` | |
| ActivityPub の匿名で取れる文書 | `public, max-age=60` | `Vary: Accept`。inbox は `no-store` |
| 外枠の HTML | `public, max-age=60, stale-while-revalidate=300` | ETag（ADR-0028） |
| ハッシュ付きのビルド成果物・ローカルのメディア（`/media/<メディア ID>/...`） | `public, max-age=31536000, immutable` | URL は内容（メディア ID）が変わると変わる |
| リモートのメディアの中継（`/media/proxy/`） | `public, max-age=<中継の保持期間>` | |
| `sw.js` など固定の URL のファイル | `no-cache` | |

- client API は ETag と条件付き GET を使わない（v0）。閲覧者つきの応答は保存させず、クライアントのキャッシュは TanStack Query だけにする。
- Service Worker は API に答えない。画面の移動はネットワークを先に使い、公開の画像だけを cache-first で持つ（ADR-0028、#203）。

## Consequences（影響）

- 自分の書き込みのあとに開いた画面は、最初の描画から書き込みを反映する（spike で、選択肢 2 の二つの変更がそろうと古い一覧が一度も出ないことを確かめた。片方だけでは出る）。
- 書き込みを書く人は「何が変わり得るか」に印を付けるだけでよく、どの画面がいつ loader で読むかを知らなくてよい。表示していないクエリの取り直しを忘れて古い表示が残る、という種類の不具合がなくなる。
- 印の付いた画面を開くと、取り直しが終わるまでいまの画面が残る（`defaultPendingMs` を過ぎると保留の表示）。書き込みのない移動の速さは変わらない。
- 印の付いた無限スクロールの一覧は、読み込んだページを全部取り直してから描画する。奥まで読んだ一覧ほど待つ（Open Questions）。
- 他のタブ・端末の書き込みは、`staleTime` を過ぎて画面を開き直すまで出ない。読んでいるタイムラインは自動では変わらない（Y7 のとおり）。
- 匿名の訪問者は、公開の一覧を最大 60 秒古く見ることがある（CDN とブラウザのキャッシュ）。
- 削除・処分されたローカルのメディアは、ブラウザ・CDN・Service Worker のキャッシュに残り得る（`immutable`、Service Worker は最大 30 日）。消すのは CDN の削除依頼など運用の範囲で、この ADR では決めない。
- 後続の作業:
  - #504: いまの S1 に合わせて、投稿・関係の変更のあとに表示していない一覧も取り直す（すぐ直す不具合）
  - #505: プロフィールの保存で、閲覧者のアカウントと埋め込みアカウントを更新する（すぐ直す不具合）
  - この ADR が受け入れられたら: loader の `staleTime: "static"` を `Infinity` に、`defaultStaleReloadMode: "blocking"` を置き、`refreshQueries` を印付けに戻し、web-client.md S1・S7 をこの方針に書き換えるタスクを作る

## Pros and Cons of the Options（詳細比較・任意）

クライアント:

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| 1. S1 を全部で守る | 画面を開くと即座に新しいデータが出る。ルーターの設定はいまのまま | 書き込みごとに、表示していない全部の一覧（キャッシュにある全アカウントのプロフィール、全タグ）を取り直す。忘れると古い表示が残り続け、今回それが起きた。`background` の再読み込みは残るので、取り直しの完了前に画面を開くと古い表示が出る |
| 2. loader が印を見る + blocking | 書き込みは印を付けるだけ。取り直しは開いた画面の分だけ。忘れる余地が小さい | 印の付いた画面は取り直しを待つ。loader の書き方（S7）とルーターの設定を変える |
| 3. キャッシュをやめる | 古い表示が出ない | 戻る・タブの切り替えのたびに待つ（E4 に反する）。サーバーの負荷が増える |
| 4. SSE で無効化 | 他のタブ・端末の書き込みも届く | 自分の書き込みの解決にはならない（届く前に画面を開ける）。購読と配る仕組みが増える |

サーバー:

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| 1. いまのまま | 閲覧者ごとの応答がどこにも保存されない。匿名の公開ページは CDN で受けられる | 匿名の一覧は最大 60 秒古い |
| 2. ETag と条件付き GET | 変わっていない応答の転送量が減る | 閲覧者ごとの ETag の計算（関係・処分で変わる）が要る。TanStack Query のキャッシュと二重になる |

## Open Questions / 要検証

- 印の付いた無限スクロールの一覧を、読み込んだ全ページでなく最初のページから取り直すか（ホームの「N 件の新しい投稿」と同じく先頭のページだけにする。戻ったときのスクロール位置との兼ね合い）
- 別のタブでの書き込みを `BroadcastChannel` で知らせるか（v0 では知らせない）
