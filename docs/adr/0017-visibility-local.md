# ADR-0017: 公開範囲 `local`（サーバーローカル）を追加する

- Status: Accepted（一部を ADR-0035（`local` 投稿の `tag` のメンション） が置き換える）
- Date: 2026-10-16
- Deciders: @rosylilly
- Issue: —

## Context

インスタンス内のコミュニティには広く見せたいが、連合で外部に拡散させたくない投稿がある。
そのための公開範囲として、サーバーの公開ローカルタイムラインには載るが、サーバーの外部へは作者のフォロワーにしか届かない `local` が必要である。

## Decision

公開範囲は次の 5 段階とし、この順で並べる: `public` / **`local`** / `unlisted` / `private` / `direct`。

### `local` の意味

| 観点 | 振る舞い |
| --- | --- |
| ローカルタイムライン | 載る |
| 連合タイムライン | 載らない |
| ホームタイムライン | 作者のフォロワー（ローカル・リモートとも）に届く |
| ハッシュタグタイムライン | 閲覧権限のある閲覧者（下記）にだけ表示 |
| 閲覧できる人 | 作者、**ログイン中のローカルアカウント**、作者のフォロワー（承認済み、リモート含む）。ブロック・凍結は常に優先 |
| 未ログインの閲覧者 | 閲覧不可 |
| リモートへの配送 | **作者のリモートフォロワーの inbox だけ**（shared inbox に集約可） |

### ActivityPub での表現

- `to` は作者の followers コレクションだけにする。`as:Public` は `to` / `cc` のどちらにも入れない。
  リモートサーバーからはフォロワー限定投稿（Mastodon の `private`）として見える。
- メンションの `tag` は残すが、**フォロワーでないリモートのメンション先には配送しない**（「外部へはフォロワーにしか届かない」を優先）。
  投稿作成時、フォロワーでないリモートアカウントへのメンションを含む場合はクライアントで警告する。
- オブジェクト URI への GET: HTTP 署名付きで、署名者がアクセス権を持つ（作者のフォロワーがいるサーバー）場合だけ返す。それ以外は 404 を返し、存在を漏らさない。
- `Update` / `Delete` は元の投稿を配送した inbox に送る（配送先を記録しておく）。

### 派生ルール

- ブースト: ローカルアカウントは `local` 投稿をブーストできる。そのブースト（`Announce`）はローカルにだけ表示し、**連合しない**。
  リモートからはフォロワー限定に見えるため、リモート側はブーストできない。
- 返信: `local` 投稿への返信の既定の公開範囲は `local`（閲覧者が変更可）。
- 投稿後の公開範囲の変更は不可（全段階共通）。
- 公開範囲の判定は、ドメイン層の単一の `canView` 関数に実装する（NFR-SEC-4）。タイムライン・検索・API・AP のオブジェクト取得はすべてここを通す。

## Consequences

- `canView` に「閲覧者がローカルアカウントか」という軸が増える。コントラクトテストとドメインのテーブル駆動テストで全組み合わせを検証する。
- リモートのフォロワーに届いた時点で、そのサーバー上での扱い（保存・表示）は制御できない（ActivityPub の本質的な制約）。UI で説明する。
- Misskey の「ローカルのみ」（連合しない）とは意味が異なる。混同しないよう、UI の文言と翻訳で区別する。
