# ADR-0039: モバイルのナビゲーションの項目と投稿の入口

- Status: Proposed
- Date: 2026-10-17
- Deciders: @rosylilly
- Issue: #328

## Context（背景・課題）

Web クライアントの外枠（[web-client.md §9](../architecture/web-client.md#9-アプリの外枠)）は、`md` 未満の画面で下端のタブバーに 7 つの項目（ホーム・ローカル・連合・検索・通知・プロフィール・設定）を等分に並べ、
その上に「投稿を書く」の文言付きの浮かぶボタンを置いている。
M3.5 の UI 監査（#328）で、実際のサーバーとクライアントを 320 / 390 px × `en` / `ja` / `ar-XB` で表示すると、次のことが分かった。

- 1 項目の幅が 45〜55 px になり、`en` と `ar-XB` で項目名が「Fed…」「Noti…」「Setti…」のように切れる。名前が切れたナビゲーションは、見える名前で探す利用者（音声入力・認知の負担）に向かない（WCAG 2.5.3 の考え方）。
- 浮かぶボタンが 320 px で画面幅の約半分を占め、タイムラインの本文と操作を隠す。検索・設定・フォローの一覧のような投稿と関係のない画面にも出る。
- 主要な類似クライアントは下端の項目を 5 つ以下にしている（Mastodon Web: ホーム・検索・投稿・通知・メニュー、[navigation_bar.tsx](https://github.com/mastodon/mastodon/blob/main/app/javascript/mastodon/features/ui/components/navigation_bar.tsx)。Misskey: 投稿ボタンを含む 5 つ前後、[mobile-footer-menu.vue](https://github.com/misskey-dev/misskey/blob/develop/packages/frontend/src/ui/_common_/mobile-footer-menu.vue)。Elk: [NavBottom.vue](https://github.com/elk-zone/elk/blob/main/app/components/nav/NavBottom.vue)）。

ナビゲーションの項目は情報設計の決定で、画面ごとの修正では決まらないので、ここで決める。関連する要件は FR-201〜207（タイムライン）、NFR-A11Y-1。

## Decision Drivers（判断基準）

1. 320 px のどのロケールでも、すべての項目名が切れずに読める（D3、NFR-A11Y-1）
2. よく使う場所（ホーム・通知・投稿）に 1 回で届く
3. ローカルと連合のタイムラインを無効にしたサーバー（FR-202）でも、同じ形で破綻しない
4. 他のクライアントから来た利用者が迷わない

## Considered Options（選択肢）

1. 7 項目のまま、項目名を `text-xs` で 2 行まで折り返す
2. 下端は 5 項目（ホーム・タイムライン・通知・検索・メニュー）。ローカル / 連合は「タイムライン」の画面のタブ、プロフィールと設定は「メニュー」のシートにまとめる。投稿のボタンはアイコンだけの浮かぶボタンにする
3. 下端は 5 項目（ホーム・検索・投稿・通知・メニュー）。投稿はタブバーの中央のボタンにし、浮かぶボタンはなくす（Mastodon Web と同じ）

## Decision（決定）

> Proposed の間は「推奨案」として書く。

**推奨案は 2。**

- 7 項目（選択肢 1）は、`ar-XB` と `en` で 2 行にしても 320 px で切れる項目が残り、タップ領域の高さも増える。
- 選択肢 3 はタブバーに「場所でない項目」（投稿）が混ざり、`aria-current` の付く項目と付かない項目が並ぶ。また投稿の入口が `md` 以上（浮かぶボタン）と違う形になる。
- 選択肢 2 は、場所（ナビゲーション）と操作（投稿）を分けたまま項目を 5 つにできる。ローカルと連合を「タイムライン」の画面のタブ（URL は今の `/local`・`/public` のまま）にすると、無効にしたサーバーでは項目ごとではなくタブが減るだけになる。
  - 浮かぶボタンは `md` 未満でアイコンだけ（アクセシブルネームとツールチップは「投稿を書く」）にし、タイムラインとプロフィールの画面にだけ出す。
  - `md` 以上のレールとサイドバーは今の項目のままにする。

覆る条件: 利用者の調査や利用の計測で、ローカル / 連合を下端から 1 タップで開く利用が多いと分かった場合は、選択肢 3 か、項目を利用者が選べる形を検討する。

## Consequences（影響）

- 320 px でもすべての項目名が読め、浮かぶボタンが本文を隠さなくなる。
- ローカルと連合が 1 タップ遠くなる。「メニュー」のシートという、新しい画面の型が 1 つ増える。
- 後続の作業: 外枠のタブバーとメニューのシート、タイムラインの画面のタブ、浮かぶボタンの出し分け（#328 の Task の分割案を参照）。[web-client.md §9](../architecture/web-client.md#9-アプリの外枠) のレイアウトの説明を、この決定に合わせて書き換える。
