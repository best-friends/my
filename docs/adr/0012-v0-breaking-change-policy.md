# ADR-0012: v0 期間中は破壊的変更を全面的に許容する

- Status: Accepted
- Date: 2026-10-16
- Deciders: @rosylilly
- Issue: —

## Context

v0 は「サービスとして利用できる状態」を最短で作るフェーズ。後方互換性への配慮は設計の自由度と速度を大きく下げる。

## Decision

v0.x の間は以下を許容する:

- DB スキーマの任意の変更。**マイグレーション履歴は持たず**、方言ごとの単一スキーマファイル（`schema/<dialect>.sql`）を編集し、DB を丸ごと作り直す（`db reset`）。
- 設定キー・API（拡張 API）・内部インターフェイス・ディレクトリ構成の任意の変更。
- データ移行ツールは提供しない。

ただし以下は v0 でも守る:

- **ActivityPub の外部仕様**: 外部実装との互換性は「後方互換性」ではなく「仕様準拠」なので壊さない。
- **連合の識別子**: 公開済みインスタンスが存在する場合、Actor URI・投稿 URI の形式を変えると連合先で別人扱いになる。
  URI 設計は M1 で確定させ、変更する場合は ADR を書く。
- 破壊的変更は PR タイトルに `!`（Conventional Commits: `feat!:`）を付け、リリースノートに記載する。

v1.0 に向けて、マイグレーション方式（ツール選定・方言別マイグレーション）を別 ADR で決める。

## Consequences

- エージェントはスキーマ変更時にマイグレーションを書かなくてよい。代わりに `schema/*.sql` の全方言を同時に更新し、コントラクトテストを通す。
- v0 の実運用者（試験運用）は、アップデートでデータが失われ得ることを README で明示する。
