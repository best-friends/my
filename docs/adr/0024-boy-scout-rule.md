# ADR-0024: ボーイスカウトルールを採用し、担当外の壊れた箇所も放置しない

- Status: Accepted
- Date: 2026-10-16
- Deciders: @rosylilly
- Issue: —

## Context

複数のコーディングエージェントが Issue 単位で並行して作業し、統括するエージェントがそれをまとめる。
各自が「自分の担当範囲ではない」という理由で、壊れたテスト・lint 違反・古くなった文書・誤ったリンクなどを見過ごすと、壊れた状態が積み重なり、後続の作業を止める。

## Decision

**ボーイスカウトルール（来たときよりもきれいにして去る）を、人間・作業エージェント・統括エージェントのすべてに適用する。**

- 作業中に見つけた壊れた箇所は、担当範囲の外でも放置しない。「自分の担当範囲ではないので無視する」は禁止する。
  - 例: 失敗するテスト、CI の不調、lint 違反、ADR と食い違う文書、切れたリンク。
- 小さく直せるもの（数行の修正、文書の食い違い）は、その場で直す。
  - 同じ PR に入れる場合は、本題と別のコミットにし、PR の説明に「ついでに直したもの」として書く。
- その場で直せない大きなもの（設計判断が要るもの、別の作業中の Issue と衝突するもの）は、Issue を起票し、作業中の Issue からリンクする。
  - 見て見ぬふりをせず、必ず記録を残す。
- 他のエージェントが作業中のファイルを直す必要がある場合は、統括エージェントに知らせ、衝突を避ける。

## Consequences

- 壊れた状態が main に残り続けにくくなる。
- 本題の差分に関係のない修正が混ざりやすくなるので、コミットを分け、PR の説明に明記する規律が必要になる。
